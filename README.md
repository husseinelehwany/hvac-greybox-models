# hvac-greybox-models
Grey-box models for buildings and HVAC systems.

## Overview

Grey-box (lumped RC) simulations of thermal zones served by VAV boxes, which are fed by an air handling unit (AHU) with an economizer. The models are driven by hourly outdoor temperature and solar irradiance from EPW weather files (Canadian CWEC) and show how zone temperatures, supply air flows, the outdoor air fraction and the coil and heater loads evolve under proportional control.

Two systems are available:

| System | Zones | Solver |
|---|---|---|
| `AHUVAVSingleZone` | one 1R1C zone, one VAV | `scipy.integrate.solve_ivp` (RK45) |
| `AHUVAVTwoZones` | two 2R2C zones, one VAV each, one shared AHU | exact zero-order-hold step with `scipy.linalg.expm` |

A Streamlit app (`app.py`) runs the two-zone system with inputs entered on schematics of the zones, VAV boxes and AHU. It also runs entirely in the browser (no Python install) through [stlite](https://github.com/whitphx/stlite).

## Quick start

```
pip install -r requirements.txt
python ahu_vav_single_zone.py      # single zone: runs and plots
python ahu_vav_two_zones.py        # two zones: runs and plots
streamlit run app.py               # GUI (two zones)
```

Run the scripts from anywhere: the `hvac_greybox` package sits next to them, and weather files are found from the package location.

## Models

### Zones

**1R1C zone** (`Zone`):

```
C · dT_in/dt = (T_out − T_in)/R + Q_hvac + Q_solar + Q_gains
```

**2R2C zone** (`Zone2R2C`), air node plus an internal thermal mass node:

```
T_out --[R_out]-- T_in --[R_m]-- T_m
                   |              |
                  C_in           C_m

C_in · dT_in/dt = (T_out − T_in)/R_out + (T_m − T_in)/R_m + Q_hvac + Q_solar + Q_gains
C_m  · dT_m/dt  = (T_in − T_m)/R_m
```

The mass (floors, furniture, inner wall layers) exchanges heat only with the air. HVAC, solar and internal gains all enter the air node.

**Solar gain** through windows uses the global horizontal irradiance from the EPW file:

```
Q_solar = A_eff · GHI,    A_eff = A_win · SHGC · F_orient · F_shade
```

`A_eff` is the effective solar aperture [m²], the usual grey-box "gA" parameter.

### VAV box with baseboard heater

```
Q_hvac = Q_rad + ρ · cp · V̇_sa · (T_sa − T_in)
V̇_sa   = V̇_min + y_cool · (V̇_max − V̇_min)
Q_rad  = y_heat · Q_rad_rated
y_cool = clip(Kp_cool · (T_in − T_sp_cool), 0, 1),   T_sp_cool = T_set + deadband/2
y_heat = clip(Kp_heat · (T_sp_heat − T_in), 0, 1),   T_sp_heat = T_set − deadband/2
```

The VAV box is controlled by a deadband proportional controller on the zone temperature (`DeadbandPController`). Above the deadband the supply air flow ramps from minimum to maximum (cooling). Below it the flow stays at minimum and the baseboard heater ramps up (heating). Inside the deadband the box runs at minimum flow with no heating.

### AHU with economizer and coil

```
T_ma = foa · T_oa + (1 − foa) · T_ra
T_sa = T_ma + Q_coil / (ρ · cp · V̇_sa)
Q_coil = clip(Kp_coil · (T_sasp − T_sa), −Q_rated, +Q_rated)
```

The coil is controlled by a proportional loop on the supply air temperature error. Because `T_sa` itself depends on `Q_coil`, this loop is solved in closed form, `Q_coil = Kp_coil · (T_sasp − T_ma) / (1 + Kp_coil / (ρ · cp · V̇_sa))`, and then clipped to the rated capacity (heating positive, cooling negative).

The economizer picks the outdoor air fraction `foa` (between a minimum and 1.0) from the outdoor, return and mixed air temperatures and the supply air temperature setpoint. The mixed air temperature used for that decision is based on the previous time step's `foa`, which breaks the algebraic loop. `foa` is then held constant over each time step.

### Two zones on one AHU

Each VAV sets its own flow from its own zone temperature. The AHU supplies the total flow at one supply air temperature, and the return air is the flow-weighted mix of the zones:

```
V̇_sa   = V̇_sa,a + V̇_sa,b
T_ra   = (V̇_sa,a · T_in,a + V̇_sa,b · T_in,b) / V̇_sa
```

The zones are thermally independent (no shared wall); they interact only through the AHU (shared `T_sa`, `foa` and coil capacity).

## Simulation approach

**`AHUVAVSingleZone`**: at each step the AHU chooses `foa`, then `solve_ivp` (explicit Runge–Kutta, Dormand–Prince 5(4)) integrates the zone temperature over the interval, with the VAV flow and heater evaluated continuously.

**`AHUVAVTwoZones`**: at each step the AHU and VAVs are evaluated from the state at the start of the step and held (zero-order hold). With those held, each 2R2C zone is a linear state-space model `dx/dt = A x + B u`, with the supply air entering as a conductance `ρ · cp · V̇_sa` in `A`. It is advanced exactly over the step with one matrix exponential of `[[A, B], [0, 0]] · Δt` (Van Loan's method). This is about 18× faster than `solve_ivp` at 15-minute steps and stays stable for the light air node.

Both `simulate()` methods return a dict of arrays: time `t`, temperatures, flows, `foa`, `T_sa`, coil, heater and VAV heat flows. Two-zone results carry `_a` / `_b` suffixes for zone values (e.g. `T_in_a`, `msa_b`) plus the AHU values (`msa` total, `T_ra`, `foa`, `T_sa`, `Q_coil`).

The component classes (zones, equipment, controllers) are independent of each other. Only the `systems` classes know how they are wired together, which is the place to add new system types.

## Usage

Import the classes from their subpackages:

```python
from hvac_greybox.zones import Zone2R2C
from hvac_greybox.equipment import AHU, VAV
from hvac_greybox.controllers import DeadbandPController
from hvac_greybox.systems import AHUVAVTwoZones

zone_a = Zone2R2C(C_in, C_m, R_out, R_m, Q_sol_a_f, Q_gains_a_f)
zone_b = Zone2R2C(C_in, C_m, R_out, R_m, Q_sol_b_f, Q_gains_b_f)
vav_a  = VAV(DeadbandPController(setpoint=22.0, deadband=2.0, Kp_cool=0.5, Kp_heat=0.5),
             msa_min=10.0, msa_max=800.0, Q_rad_rated=1000.0)
vav_b  = VAV(DeadbandPController(setpoint=22.0, deadband=2.0, Kp_cool=0.5, Kp_heat=0.5),
             msa_min=10.0, msa_max=800.0, Q_rad_rated=1000.0)
ahu    = AHU(Q_coil_rated=2400.0, T_sasp=18.0, Kp_coil=1000.0, foa_min=0.2, foa0=0.2)

model = AHUVAVTwoZones(zone_a, zone_b, vav_a, vav_b, ahu, T_out_f)
res   = model.simulate(t_series, T_in0_a=20.0, T_in0_b=20.0)
```

The `*_f` arguments are `scipy.interpolate.interp1d` interpolators of time series (outdoor temperature, solar and internal gains) over time in seconds. Parameters for the scripts are set at their top; for the app, in the Inputs tab.

To install the package for use outside this folder (e.g. notebooks), run `pip install -e .` from the repo root. Optional extras: `pip install -e ".[app,dev]"` adds Streamlit and pytest.

## Requirements

Python 3.9+ with `numpy`, `scipy`, `matplotlib`, `pandas` and (for the GUI) `streamlit`; see `requirements.txt`.

## Units

Temperatures in °C, heat flows in W, thermal capacitance in J/K (MJ/K in the app), thermal resistance in K/W, time in s, irradiance in W/m², and supply air flow in L/s (volumetric).
